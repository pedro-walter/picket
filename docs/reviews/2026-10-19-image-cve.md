## traefik:v3.7 (registry, soul-spike, monitoria-soul-spike) — 12 findings (4 per agent)

`usr/local/bin/traefik`: stdlib (CVE-2026-78667, 97031, 78669) and golang.org/x/net (CVE-2026-78669).

**This changed since last week: re-pull.** All three hosts scan digest `sha256:575fa15b…`, which is the v3.7.14 build.
`v3.7` was rebuilt on Docker Hub on 2026-10-16 as **v3.7.15** (digest `sha256:0f615020…`). Its `go.mod` has
`golang.org/x/net v0.60.0`, which is the x/net fix. v3.7.15 also lists three security advisories and a migration-guide
link: read https://doc.traefik.io/traefik/v3.7/migrate/v3/#v3715 before recreating, since it rejects CONNECT requests
in every HTTP version.

Not verified: that the shipped Go toolchain is >= 1.26.9 (the stdlib CVEs). `go.mod` says `go 1.26.0`, which does not
tell us. Rescan decides. No rule: they should clear on re-pull, and a suppression would hide that.

```sh
docker compose pull traefik && docker compose up -d --force-recreate traefik   # on all three hosts
```

If the stdlib findings survive the rescan on v3.7.15, reuse last week's rules with the new date:
`for c in CVE-2026-78667 CVE-2026-97031 CVE-2026-78669; do picketctl rules add --kind image-cve --subject traefik --identifier "$c|stdlib" --cve $c --reason "<recheck>" --expires 2027-01-17 --inherit none; done`.

## ghcr.io/project-zot/zot:v2.1.22 (registry) — 4 findings

**Suppressed 2026-10-19 at the operator's request** (4 rules, `inherit none`, expire 2027-01-17); commands below were run.

Same CVEs as traefik (stdlib, x/net), but zot ships Go 1.27.1 (fixed in 1.27.2) and x/net 0.59.0 (fixed in 0.60.0). `v2.1.22` (2026-10-06) is still the newest release; none newer. Nothing to bump,
nothing to overlay (compiled Go binary). Wait for v2.1.23. Optional suppress, short expiry; this is a "no fix
published" decision, not a reachability argument (zot is an exposed registry, so net/http is on its path):

```sh
for c in CVE-2026-78667 CVE-2026-97031 CVE-2026-78669; do
picketctl rules add --kind image-cve --subject ghcr.io/project-zot/zot --identifier "$c|stdlib" --cve $c \
  --reason "No zot release newer than v2.1.22 (2026-10-06) as of 2026-10-19; it ships Go stdlib 1.27.1, fixed in 1.27.2. Availability-only DoS; zot sits behind Traefik. Re-check at next zot release." \
  --expires 2027-01-17 --inherit none
done
picketctl rules add --kind image-cve --subject ghcr.io/project-zot/zot --identifier 'CVE-2026-78669|golang.org/x/net' --cve CVE-2026-78669 \
  --reason "No zot release newer than v2.1.22 (2026-10-06) as of 2026-10-19; it ships x/net 0.59.0, fixed in 0.60.0. HTTP/2 SETTINGS flood DoS, availability-only; zot sits behind Traefik. Re-check at next zot release." \
  --expires 2027-01-17 --inherit none
```

re-pull may clear. The remaining findings are compiled binaries or .NET deps.json entries that an apt/apk overlay
can't patch. If a re-pull leaves the cleanuparr openssl or jellyfin curl findings open, those two become category B
candidates next pass (the Dockerfiles would be on Ubuntu with `apt-get install --only-upgrade`).

Images with no clean recommendation: bazarr (Js2Py, no fix anywhere). Nothing was built, pushed, or run against
