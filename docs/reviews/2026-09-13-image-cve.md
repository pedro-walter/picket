## Cross-image pattern: CVE-2026-14456 (Alpine `openssl` QUIC DoS)

Appears in **postgres**, **traefik**, and **tecnativa/docker-socket-proxy**
— all three are Alpine 3.24.1-based and pin `libcrypto3`/`libssl3`
`3.5.7-r0`, fixed in `3.5.8-r0`. One root cause, three findings; treat as
one decision, not three.

`postgres:16-alpine` and `traefik:v3.7` are **rolling** tags (Docker
rebuilds them in place on a cadence — `postgres:16-alpine` was last pushed
2026-08-16, `traefik:v3.7` tracks `v3.7.13` released the same day) that
haven't picked up the Alpine security fix yet. `docker-socket-proxy:v0.5.0`
is a **frozen** release tag — it will never get a newer package on its own.

**Action: re-pull now, suppress the gap with a short expiry, don't
custom-rebuild for this one.** These base images cycle every few weeks;
a plain `docker compose pull && up -d` in ~2-3 weeks very likely resolves
postgres/traefik without any custom image. `docker-socket-proxy` won't
self-resolve, but a whole custom rebuild for one shared library in a
proxy this small isn't worth it before the wait window; revisit at the
next review if libcrypto3/libssl3 are still open at that image's frozen
tag.

```sh
cd cli/picketctl
EXP=$(date -u -d '+21 days' +%Y-%m-%dT%H:%M:%SZ)
./picketctl rules add --kind image-cve --subject postgres \
  --identifier '*|libcrypto3' --cve 'CVE-2026-14456' \
  --reason "Alpine 3.24.1 base openssl QUIC DoS, fixed in 3.5.8-r0; postgres:16-alpine is a rolling tag (last rebuilt 2026-08-16), expect the fix on its next automatic rebuild - re-pull and rescan before this expires." \
  --expires "$EXP"
./picketctl rules add --kind image-cve --subject postgres \
  --identifier '*|libssl3' --cve 'CVE-2026-14456' \
  --reason "same as libcrypto3 above - Alpine base openssl, rolling tag, expect auto-fix on next rebuild." \
  --expires "$EXP"
./picketctl rules add --kind image-cve --subject traefik \
  --identifier '*|libcrypto3' --cve 'CVE-2026-14456' \
  --reason "same Alpine 3.24.1 openssl QUIC DoS; traefik:v3.7 is rolling and tracks v3.7.13 (released 2026-08-16), expect auto-fix on next rebuild." \
  --expires "$EXP"
./picketctl rules add --kind image-cve --subject traefik \
  --identifier '*|libssl3' --cve 'CVE-2026-14456' \
  --reason "same as libcrypto3 above." \
  --expires "$EXP"
./picketctl rules add --kind image-cve --subject tecnativa/docker-socket-proxy \
  --identifier '*|libcrypto3' --cve 'CVE-2026-14456' \
  --reason "same Alpine openssl issue; v0.5.0 is a frozen release tag so it won't self-resolve - revisit next review, custom-rebuild if still open." \
  --expires "$EXP"
./picketctl rules add --kind image-cve --subject tecnativa/docker-socket-proxy \
  --identifier '*|libssl3' --cve 'CVE-2026-14456' \
  --reason "same as libcrypto3 above." \
  --expires "$EXP"
```

## postgres (pinned `16-alpine`, rolling tag, last rebuilt 2026-08-16)

| package(s) | target | CVEs | sev | fix published | action |
|---|---|---|---|---|---|
| libcrypto3, libssl3 | postgres (OS layer) | CVE-2026-14456 | high | yes (3.5.8-r0) | see cross-image note above |
| libuuid | postgres (OS layer) | 7 util-linux CVEs (76642, 78408-78410, 53612-53614) | high | yes (2.42.3-r0) | same rolling-tag logic — re-pull in ~3 weeks, suppress meanwhile |
| stdlib | `usr/local/bin/gosu` (vendored helper binary) | 22 CVEs (crypto/tls ×3, crypto/x509 ×4, net/net/http/net/http2 ×4, net/url ×2, net/mail ×2, encoding/asn1, encoding/xml, html/template, mime, golang ×2) | high/critical mix | yes, in newer Go toolchains | **suppress** — see below |

`gosu`'s entire job is `setuid()`/`setgid()` then `execve()` into the real
entrypoint — it opens no network connection, parses no HTTP/TLS/XML/mail
input. Every one of the 22 flagged stdlib subpackages
(`crypto/tls`, `net/http`, `net/url`, `net/mail`, `encoding/xml`, …) is
unreachable code in that binary by construction. This is the strongest
"safe to suppress" case in the whole review — it's tied to gosu's known,
narrow purpose, not a guess from the package name.

```sh
EXP=$(date -u -d '+90 days' +%Y-%m-%dT%H:%M:%SZ)
./picketctl rules add --kind image-cve --subject postgres \
  --identifier '*|stdlib' --cve '*' \
  --reason "Go stdlib CVEs compiled into usr/local/bin/gosu, the postgres image's setuid-then-exec helper - it never touches network/TLS/HTTP/XML, so crypto/tls, net/http, net/url etc. findings here are unreachable code. Fixed upstream in newer Go toolchains; will clear once the postgres image rebuilds gosu. Re-check membership if postgres's Dockerfile ever changes how gosu is built in." \
  --expires "$EXP"

EXP21=$(date -u -d '+21 days' +%Y-%m-%dT%H:%M:%SZ)
./picketctl rules add --kind image-cve --subject postgres \
  --identifier '*|libuuid' --cve '*' \
  --reason "util-linux CVEs in the Alpine base layer, fixed in 2.42.3-r0; postgres:16-alpine is a rolling tag, expect auto-fix on next rebuild - re-pull and rescan before this expires." \
  --expires "$EXP21"
```
