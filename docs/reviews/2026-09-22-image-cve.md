## Getting the data this pass required fixing an auth blocker first

`picketctl findings` failed outright at the start of this run: `/admin/*`
on `picket.souspike.com.br` is now sitting behind a Cloudflare Access
application (added since the 2026-09-20 review, evidenced by the
still-uncommitted `server/src/access.ts`, `auth.ts`, `index.ts`,
`wrangler.toml` diffs), and `picketctl` only ever sent `X-Admin-Token` —
which the Worker stops accepting entirely for `/admin/*` once
`CF_ACCESS_TEAM_DOMAIN` is configured. Cloudflare Access was redirecting
every `picketctl` request to its login page instead of returning JSON.

Resolved with the user in-session, not something this skill does on its
own:
- Added `CF-Access-Client-Id`/`CF-Access-Client-Secret` header support to
  `cli/picketctl/picketctl`'s `req()` (a Cloudflare Access **Service
  Token**, set up by the user in the Zero Trust dashboard with a
  Service-Auth policy on the app covering `/admin/*`).
- That alone still 401'd: `server/src/access.ts`'s `verifyAccessJwt` only
  ever checked the JWT's `email` claim, but a Service-Token-authenticated
  JWT carries `common_name` instead (Cloudflare's own convention for
  distinguishing machine auth from a human login) and has no `email` claim
  at all. Added `common_name` as a fallback identity. Deployed by the user
  (`npx wrangler deploy`) — confirmed via `wrangler tail` that the JWT was
  reaching the Worker before the fix and that requests succeed after it.

Both changes are small and mechanical (auth plumbing, not policy), but
they're still sitting **uncommitted** in the working tree, mixed in with
the rest of the in-progress Access rollout diff (`auth.ts`, `cron.ts`,
`index.ts`, `ingest.ts`, `notify.ts`, `wrangler.toml`, `docs/setup.md`) —
worth a deliberate commit rather than letting it keep riding along
uncommitted like the 2026-09-16 overlay work did.
